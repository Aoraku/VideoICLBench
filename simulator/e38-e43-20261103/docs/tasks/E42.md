# E42：用铲沿推球到图形区域

这是维护者说明。下表用于核查任务与评分，**不能作为额外提示发给模型**；模型应从该输入组允许的指令、示范和正常观测中获取规则。工程参考策略与检查点信息同样不能进入模型观测。

## 目标与 ABC

机器人持源铲，用真实铲沿把粉球、红球推到同一个指定标记纸区域。图形是纸区的身份标记，不能额外要求球位于墨线内部或纸区中心。

| 变体 | 两球的目标 |
|---|---|
| A | 圆形标记纸 |
| B | 三角形标记纸 |
| C | 方形标记纸 |

当前验收范围为 **I / seed4201 / ABC**。I 改物体实例与初始排列，保留上述对应规则；不同变体的完成证据分别统计。

## 物理动作与原生条件

必须实际抓住铲柄，以源铲曲面前缘接触、推动桌面上的球；不能用手搬球、另一件握持工具送球，或仅用宽面、柄部擦碰冒充铲沿推送。末态两球应已释放、稳定、受到实际支撑，并被原生判定在目标纸区。

原生六项检查为 `released`、`stable`、`two_balls_in_paper_region`、`balls_supported`、`actual_edge_push`、`delivery_has_continuous_tool_cause`。v3 按固定源网格识别真实曲边；只累积相邻、有效接触物理 tick 的位移净向量，反向运动抵消。短暂脱离不计位移、不跨空中连接样本；手或其他握持工具介入会使因果来源失效。当前实现仍保留每球有效驱动净位移大于 20mm 的门控；这是实现中的因果证据阈值，不应改写成给模型的新任务要求。

## 运行

先按根 README 配置 Isaac、机器人资产和数据仓库中的资产根、bindings、profile。E42 v3 曲边和因果门控默认加载，无独立物理开关。以下是**无模型/API的维护者工程运行**，在交付的 `runtime` 目录执行，输出目录须全新：

```bash
python scripts/probe_realworld_room_pool.py \
  --bindings "$BINDINGS" --robot "$PROFILE" \
  --tasks E42 --variant B --seed 4201 \
  --execution-control positive --execution-action-budget 3000 \
  --execution-settle-ticks 600 --settle-ticks 240 --ticks 25 \
  --headless --device cpu --out "$NEW_OUTPUT"
```

Isaac 所需 `--experience` 与 `--kit_args` 沿用根 README。模型运行使用正常任务入口，不调用工程 expert。工程参考的整手/铲体扫掠、上部真实铲沿接触与前移握柄只用于合法动作实现，不改变任务物理或评分；路径提案有20秒、24候选预算，超预算保存检查点，不宣称物理不可达。既有原生入口禁止直接重放。


也可直接使用本交付根入口：

```bash
/path/to/isaaclab/python.sh run.py --task E42 --variant B --out outputs/e42-b
```
