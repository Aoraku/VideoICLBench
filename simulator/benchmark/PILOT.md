# 六题 pilot：作者验收与仿真示范

本阶段验证的是“任务是否可通过给 agent 的同一动作字母表完成”，不是独立 agent 成功率。作者控制器读取了私有物体位置／夹持状态，因此只能作为工程可解性验收。全部移动仍调用 `DesktopDual.action(left,right)`；没有瞬移、设置 qpos、注入成功状态或额外控制通道。

最终验收数据见 [pilot_validation.json](pilot_validation.json)：六题均在 A 布局、seed 0 下执行作者规划，再将动作列表通过独立策略进程和 actor API 重放。仿真录像与完整轨迹保留在 Agentlab 外部数据目录，不进 Git；媒体有 SHA256 与任务版本。B/C 布局、多 seed 和 fresh-context agent 尚未完成验收，不从 A/0 工程成功推导它们的表现。

## 发现与修订

| 任务 | 工程试验发现 | 验收策略／修订 |
| --- | --- | --- |
| rt12 夹杯 | 原始固定动作已能完成；需要确认统一控制器与 API 一致 | 合法动作夹取、搬运、松开；目标仍是桌面杯子，不是历史微波炉题 |
| rt07 空中交接 | 最初 50 mm 立方体代理和 130 mm 长块的试验发生夹爪／腕部干涉；固定接近点还会因物体下垂而失准 | 修订为 44×280×50 mm 长块，沿桌面 Y 方向提供分离夹持位置，接收臂跟随实际夹持端点；放大目标垫以容纳长块。任务版本变为 2 |
| rt02 三层塔 | 用同一侧机械臂跨到另一侧取最后一块时，把块推偏 | 先把底块移到共享区域，再逐层叠放；目标关系仍是蓝底、绿中、红顶 |
| rc10 锅间转移 | 容器壁与张开的夹爪发生接触，物体夹起后脱落 | 旋转夹爪，使用来源侧机械臂取物，再经共享区域暂放，由另一臂完成入碗；桌面暂放不是交接题的成功替代 |
| rc22 瓶子互换 | 夹取高度过低会撞倒瓶子；跨侧直抓不稳 | 抬高瓶子的夹取点，利用两个中间位置与各自侧的机械臂进行交换 |
| rc11 食材分类 | 两件物体分别放入指定碗，可使用各自侧机械臂完成 | 保留实际容器底板、完整边界、接触和松开后的稳定判分 |

这里的失败描述只针对已运行的作者轨迹，**不证明原尺寸或其他策略不可解**。源任务审阅也发现 RoboTwin `handover_block` 本来使用 60×60×200 mm 长块，具有分离抓取点；最初的立方体代理没有保留这个重要结构。当前 44×280×50 mm 横放几何是针对 Panda 和桌面操作的明确适配，不是上游原生尺寸。具体来源 commit 链接仍在 tasks.json。

交接判分加严为：先由 arm 0 离桌夹持，随后 arm 1 在 arm 0 已松开时独占夹持至少 4 个控制 tick（20 Hz 下 0.2 s）。双方同时触碰、桌面中转都不能获得交接事件。末态还必须满足目标垫摆放、松开和稳定要求。

录像从初态开始，按每次原子动作采样（2.5 fps）；达到最终成功并稳定 2 s 后停止采集。作者控制器可以继续收臂，但不在视频中加入无关的长尾；录像无剪辑和目标文字。该低帧率工程示范足够验收导入／16 帧流程，不替代后续高帧率正式采集。

## 复现

在隔离 Python 环境中运行：

```bash
python -m simulator.benchmark.pilot --tasks rt12 rt07 rt02 rc10 rc22 rc11 \
  --variant A --seed 0 --record --output /absolute/path/pilot-A0
```

Linux 设置 OSMesa；macOS 使用正常图形上下文。输出目录必须是新的，失败试验也保留，不能覆盖掉失败证据。结果有任务版本、源代码哈希、动作哈希、完整私有判分和状态日志；视频只显示原生相机。

检查六段录像和结果后，通过实际 actor API 验收：

```bash
python scripts/embodied50/accept-pilot.py \
  --pilot-folder /absolute/path/pilot-A0 \
  --data /home/qingle/services/videoicl-embodied-50/data \
  --output /absolute/path/pilot-replay \
  --author-reviewed
```

脚本检查源代码冻结、六题全部成功、任务版本匹配；随后导入仿真示范、经 runner 创建 `author_replay` 轮次、逐动作重放并验证最终成功。已有同版本示范保持不可变，不会覆盖；新录像仍保存在 pilot bundle 中。运行中的 actor 服务也必须是该代码版本。

`run` 现在必须显式指定 `--trial-kind agent|author_replay|protocol_smoke`。手动 GUI 默认是 `manual_author`。标签写入作者 manifest 与私有结果，避免把工程回放误报成 agent 成绩。旧版本示范不能用于修订后的题目；缺少版本的旧 manifest 仅按版本 1 处理。

## 人手采集包

先采这六题，每题只录 A；任务目标与摆放图参考 tasks.json，禁止把作者清单和目标坐标提供给 demo-only agent。

| 题号 | 需要准备的主要道具（毫米） | 人手演示要点 |
| --- | --- | --- |
| rt12 | 红色开口方杯 68×68×84；灰垫 200×180 | 从初始位置夹杯，移到垫上，松手 |
| rt07 | 红色长块 44×280×50；灰垫 200×340 | 左手夹起，一次真正离桌交给右手，由右手放到垫上；不以桌面中转代替 |
| rt02 | 红、绿、蓝三块，各 50×50×50 | 蓝在底、绿在中、红在顶；可以移动底块，重点是关系和稳定 |
| rc10 | 红色食材块 36×36×36；蓝／绿开口方碗各 130×130×50 | 食材初始在来源碗，演示转到目标碗；允许合理的中间暂放 |
| rc22 | 红、蓝圆柱瓶，直径44、高110 | 交换两个瓶子的原位置，不只是集中到同一处 |
| rc11 | 红、黄食材块各 36×36×36；蓝／绿开口方碗各 130×130×50 | 两份食材进入不同目标碗，颜色对应要清楚 |

开口道具不是实心盒。杯／碗壁厚 8 mm（模型几何半厚度 4 mm），底板厚 8 mm；真实道具尽量对应这些内腔尺寸。固定斜俯视，整桌和双手可见，开始与结束都静置至少2 s，无字幕、剪辑或口头目标泄漏。文件可以命名 `rt12_A_human.mp4` 等；实际录好并由作者检查后再使用 `demos` 导入，不能拿仿真录像伪装成人手示范。
