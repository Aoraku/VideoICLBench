# Astra 具身实验 · 2026-11-06

本交付用于在自己的 Linux/IsaacLab 机器上准备 Astra 的具身实验。物理执行和视频问答共享 API 门控，各有独立的输入、工具、运行身份和评分方式。工程分沿用当次任务协议。

## 实验清单

| 实验 | 配置 | 身份数 |
|---|---|---:|
| 主表 | 50 题固定 C 版，文本规则和真实视频各一次。42 题使用换物体环境 I，8 题使用复现环境 R | 100 |
| 泛化与 ablation 4 | 同一 17 题子集，使用清单中支持的 R/I/E 环境和 text/real/sim 输入；两项实验共用结果 | 138 |
| ABC 对照 | 同一子集，真实视频补跑 A、B；C 已含在前两行 | 34 |
| 无规则输入 | 同一子集，固定 C，保留任务目标 | 17 |
| 独立视频 QA | 同一 17 题 × A/B/C；真实视频、四选一，按首个有效答案离线评分 | 51 个答案 |

主表和泛化有 34 个相同身份，物理执行去重后为 **255**（100 + 138 − 34 + 34 + 17）。51 个 QA 另计。原实验新启动了 254 条物理执行，E22C-I-real 复用了此前核对匹配的结果。复现时请分别报告独立运行和有凭据的复用。

## 一次物理执行

1. 每条 episode 固定任务、版本、环境、输入条件和 seed 4201，独占一个 Codex 原生 session。第一轮包含任务说明、该条件允许的示范信息、初始完整 GUI 和公开机器人状态。GUI 保留三路相机小窗。
2. 模型可组织多对有序动作，一次 Commit 后由仿真执行，再返回最终 GUI、公开状态和动作回执。模型可以主动请求观察、历史、视频帧或指定像素的深度。视频输入按需取帧，文本输入不给视频。
3. 本批配置固定 Codex CLI 0.163.0、gpt-6-astra、high、262144 token 窗口、120000 token 原生自动 compact、500 个物理动作、无 episode 时间上限。一次 Commit 最多排 24 对动作；是否需要新的观察由模型决定。
4. 执行池与 QA 共用 **50** 个上游请求名额。一次采样的在途数、等待同池动作的房间数、已结束的 episode 数应分别报告。恢复前核对 session、已接受动作和请求账本；上游状态不明时保留原世界。
5. 成功取自原生物理终态。Done 表示模型请求结束，可能得到部分分或 0。此次允许工程环境运行；完整物理正负对照验收和统一 0/40/100 重评需另作记录。

## 读成绩与 token

对单个已运行房间执行 `python3 reporting/read_score.py "$ROOM/environment"`。输出包含 terminal、success、score 和 source。主表按固定 C 版的 100 个身份对齐。未结束、已结束但证据缺失、明确的工程零分分开记录。

这批 E01/E09/E17/E20/E39 的执行设计评分器把有效工程分写在原生终态 evidence 中。E26 的按铃评分器把原始过程分写在 evidence.progress_result 中。读取器在顶层为空时分别验证协议和证据，只对 E26 已核实、与原生成败吻合的两个端点取值，其余保留 null。它不修改原始裁决文件。

分析消费时按 episode 和请求 ID 对账，同时区分模型决策、原生 compact、重试和本地拒绝。缓存命中属于输入 token 的子集。累计输入是多次请求之和，不能当作单次上下文长度。判断原 session 是否恢复，要同时看到成功响应与后续原生动作或终态证据。
