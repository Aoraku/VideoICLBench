VideoICL 任务设计手册

设计原则 难度体系 逐题示范与执行规范

本手册面向任务设计者、视频录制同事与评测维护者，覆盖 75 道 Web 任务、36 道 OS 任务和 8 道具身任务，共 119 个任务族与 357 个 A/B/C 条件。评测的核心是从清晰的视频示范中学会可迁移的方法，再在独立的新实例中完成目标。执行难度由业务依赖、状态变化和物理交互决定。

本手册包含完整 A/B/C 规则，供团队设计与审阅使用，不作为 agent 的 inference prompt。

设计原则

视频教会明确的方法。示范应清晰呈现输入、处理动作和结果。文本题明确整段、逐词、逐字符或逐行的作用范围；分类题同时呈现命中与未命中对象；阈值题覆盖边界；选择题让竞争属性对应不同候选；排序题说明稳定性与并列约定。视频长度以足以辨认关系为准，不能通过信息缺失或歧义提高难度。

Demo 与 inference 职责独立。Web 各难度的 demo 均只展示方法及必要操作，从默认首页保留进入操作页的自然导航。资料汇总、跨模块办理、跨平台交付等完整业务链属于 inference。停止判断等依赖动态过程的示范须保留触发条件前后的必要过程。视频与执行应用可以不同，但字段和动作的对应关系必须明确。OS 配套示范呈现局部交互关系；具身示范呈现关系及其必要物理实现过程，不以轨迹长度冒充额外规则。

Prompt 是目标加约束。执行者获得需要完成的成果、处理范围、限制条件及必要公共参数，且明确应从视频学习哪一种对应关系、选择顺序或转换格式。Prompt 不给 A/B/C 的答案，不提供按钮级路线。软件显示联系人、文件、业务通知、来源资料与已保存状态；评测目标和教程说明由外部 prompt 提供。

一个 episode 对应一个持续环境。同一应用内的多份消息、文章、歌曲或答案是同一资料库里的对象，操作按对象编号保存。应用导航只改变查看位置。涉及多平台时，应用切换入口连接同一个 run 的共享数据与真实文件；切换不重置状态、不替换任务实例，也不显示解题进度。

A/B/C 是反事实对照。同一任务在相同 seed 下保持输入环境和业务目标一致，三个条件分别提供对应版本的视频，使用独立的模型上下文与运行状态。三个版本是三次独立评测，不是一次 inference 中要完成的三个清单项。Demo 的实例与 inference 的实例分开，避免直接复制对象编号或答案。

依据真实结果判分。评测器读取实际保存的文本、标签、集合、顺序、消息、提交记录和物理状态，同时检查未命中对象、来源关联与接收对象。严格成功要求所有必要条件满足；检查项完成度用于诊断部分成功，不代替严格成功。多对象题不得因最后一项正确而覆盖前面错误。需要交付文件的任务检查文件内容与实际业务状态一致。

规则理解与执行能力分别分析。可在观看视频后用独立 QA 测量关系理解，再观察在线执行结果。无视频、错配视频和正确视频构成有用的对照。任务级成功率、检查项完成度与失败类型应一起报告，人工难度标签不能替代实测模型成功率。

难度分级

Web 的低中高按执行结构划分，各 25 题。所有等级使用同样清晰的示范要求。

等级执行结构必要判分依据
Web 低在同一应用数据库中处理多个对象。文本题通常有三份资料，生成内容分类有十二条；棋盘题在同一棋谱库保存三份不同棋盘，逐一分类或作局部决策。逐对象结果和未命中对象的保持；三份棋谱分别核对合法操作及条件，并提供部分完成度。
Web 中围绕一个交付目标完成同平台多模块业务，关联独立资料、制作成果并交付。视频方法是其中的一个环节。有效请求、范围、实际处理结果、资料关联、可下载成果及接收地址。
Web 高跨两个或多个平台的完整业务流程，后续操作消耗前序真实结果或文件。源数据、实际保存状态、跨平台内容一致性、正确接收人和可追溯交付。

棋盘选点基线可能只需一次决策，不能据其标签宣称具备长程难度。长度、难度与规则复杂度是不同维度：重复次数增加执行负担，状态依赖与跨应用资料关联增加规划负担，物理接触增加控制负担；含糊规则、等待时间和无意义点击不构成设计难度。

OS 分为 Easy、Medium、Hard，各 12 题。Easy 在一个持续桌面中对多个新对象重复应用同一方法；Medium 在一个主要应用中完成长程业务，视频方法只是其中一个模块；Hard 在此基础上要求 File Explorer、Notepad、Settings、Task Scheduler 等桌面应用之间有真实内容或状态依赖。应用切换不重置环境。Demo 由人录制，覆盖同一规则的多次实现，不演示完整长程 query。三档都是执行结构标签，不代表模型实测成功率。

具身任务分别保留长度和难度：简单 2 题，中等 3 题，困难 3 题；短程 3 题，中程 3 题，长程 2 题。难点来自重排、遮挡下取件、结构恢复、真实套入和非抓取接触控制。配套视频来自仿真作者控制器；难度标签不表示独立 VLM 已验证的成功率。

视频来源：同事录制的规则示范

B本版本：空格改为下划线。打开“通讯录”，选该联系人，点“查看完整资料”，找到备注输入框；不要修改其他联系人的姓名。 返回通讯录核对新备注，并让原始姓名与修改结果都在视频中清楚出现。

C本版本：全部转为小写。打开“通讯录”，选该联系人，点“查看完整资料”，找到备注输入框；不要修改其他联系人的姓名。 返回通讯录核对新备注，并让原始姓名与修改结果都在视频中清楚出现。

Inference 执行什么

请为团队完成《参会人员名册》，交付给有效业务请求指定的责任团队。 其中，姓名到备注姓名的格式转换方式请采用示范视频中展示的方法。

采用业务收件箱中同一请求编号的最高修订；处理范围、截止日期和接收团队以该请求为准。范围外对象保持原状。

列入本次发布项目的全部五位成员，每人一行。通过成员账号/对象编号匹配席位，不能只按相似姓名匹配。

每条参会成员须对应应用中的实际保存结果，并按对象编号关联《会务席位表》中的“席位与职责”；文件行内容、来源和接收邮箱须准确，接收者能下载完整成果。

春季发布组的五位成员已各自发来姓名。请从群成员名单确认身份，按视频格式修改各人的备注昵称；成员账号用于区分同名人员，群外人员不变。

学习关系：姓名到备注姓名的格式转换方式

最终成果：已交付的《参会人员名册》：包含对象编号、应用中的保存结果、对应来源记录及“席位与职责”，并记录正确接收邮箱。
