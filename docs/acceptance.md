# 验收矩阵

## 开发工作台

任务 1–65 使用共享的开发业务状态服务；任务 66–75 使用确定性棋盘引擎。开发界面只公开对象属性和普通操作，私有判分器持有 A/B/C 规则。开发工作台用于验证任务可表达性、规则生成、输入接口和录制流程。

开发数据与正式数据之间必须隔离。已有测试检查同一输入的三个版本产生不同结果，并拒绝将示范字符串答案直接复制到评测实例。

## 业务语义门槛

开发工作台中的通用操作记录不能替代以下实际业务证据：发送消息必须写入对应收件人会话；建群必须有真实成员关系；购物车必须体现增删；转账必须同时具备账本与余额变化；复制必须从被测环境的实际剪贴板采集。

此外，任务 59 的文本变换不能借用代码编译结果判分；任务 60 需要接受保留语义的合法变量重命名；选择题的元数据和 UI 展示必须一致；游戏任务的已操作棋盘不允许自行伪造结果。

## 系统任务

Windows 76–90、Linux 92–98、Android 91/99/100 均需要真实执行池、初始化与判分适配器。配套工具任务必须标记 assisted-system。生命周期 Worker 和文件采集脚本不是全部 25 题的完整实现。

## 发布条件

正式成绩只允许来源于经过认证的执行表面、固定镜像和审核通过的视频。开发工作台及自动生成的冒烟测试视频均不得混入正式结果。
