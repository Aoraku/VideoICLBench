# VideoICL-Bench：面向交互式智能体的视频上下文学习评测

## 1. 项目概述

VideoICL-Bench 旨在评测 VLM/Agent 能否从一段短教程视频中理解新的任务规则，并将其迁移到真实、可交互的数字环境中完成任务。

其典型应用场景是：用户第一次接触某个企业内部平台，仅向智能体提供一段操作教程视频，智能体需要理解视频中的操作流程和内部规则，随后在 Linux、Android 或 Windows 环境中独立完成同类但不完全相同的任务。

该评测同时覆盖智能体面临的两项核心挑战：

1. 从视频中理解操作过程、条件关系和隐含规则；
2. 在动态平台中规划并执行多步操作，而非仅生成文本答案。

## 2. 核心研究问题

VideoICL-Bench 关注以下问题：

- 智能体能否从视频中提取可迁移的任务规则？
- 智能体能否将理解到的规则应用于新的任务实例，而非机械复现视频轨迹？
- 智能体的成功是否真正依赖教程视频，而非模型训练阶段获得的先验知识？
- 任务失败主要源于视频理解、规则推理，还是在线操作能力不足？
- 不同的视频信息表示方式如何影响学习和执行效果？

## 3. 避免先验知识干扰

Benchmark 通过两种互补机制确保任务必须依赖教程视频完成。

### 3.1 未见过的自建平台

评测环境采用自主搭建的平台，包括：

- 两个通讯软件；
- 一个音乐检索软件；
- 一个新闻软件；
- 一个在线判题平台；
- 一个五子棋游戏；
- Linux、Android 和 Windows 系统操作任务。

平台界面、功能逻辑和交互流程不依赖公开软件，降低模型通过训练数据记忆完成任务的可能性。任务设计不受既有平台限制，可根据评测需要调整平台逻辑或增加新的环境。

### 3.2 反事实任务规则

每个任务设置多个界面和任务情景相同、但内部规则不同的版本。例如：

- 将字符串转换为“首字母小写、其余字母大写”；
- 将字符串转换为“仅末尾字母大写”；
- 根据某种特征将对象归入绿色类别；
- 在另一版本中交换绿色与红色的分类规则。

这些规则完全由教程视频定义，且可以违反常识或与模型先验相冲突。同一模型面对相同任务情景时，必须根据不同视频执行不同操作；忽略视频的智能体无法在这些互相冲突的版本上稳定成功。

## 4. 数据集设计

Benchmark 计划包含 100 个基础任务。每个任务制作三个反事实规则版本，共形成：

- 100 个任务情景；
- 每个情景对应 3 套规则；
- 共 300 段人工录制的教程视频；
- 每段视频长度约 20 秒。

同一任务的三个版本保持平台、界面、任务目标和整体难度一致，仅改变视频定义的关键规则，从而形成严格可控的对照。

每个评测样本由三部分组成：

1. **教程视频**：展示任务操作方法及其规则；
2. **规则理解 QA**：检测智能体是否正确理解视频中的关键规则；
3. **在线执行任务**：要求智能体在可交互环境中将规则应用于新的任务实例。

执行环境支持状态重置，并通过平台接口自动检查任务结果和中间状态。

## 5. 评测指标

### 5.1 任务完成度

通过环境接口判断任务是否完成，并根据关键状态或子目标计算整体完成度。这是衡量智能体端到端视频学习与在线执行能力的主要指标。

### 5.2 规则理解准确率

在观看视频后、进入环境前，通过 QA 检查智能体是否识别了视频中的操作规则、条件关系和关键约束。

### 5.3 理解—执行联合分析

结合 QA 与执行结果区分不同失败来源：

- QA 错误、执行失败：主要受限于视频理解或规则推理；
- QA 正确、执行失败：主要受限于规划、界面定位或在线操作；
- QA 正确、执行成功：完成从视频学习到实际执行的完整迁移；
- QA 错误、执行成功：可能依赖猜测、先验知识或偶然命中。

同一任务三个反事实版本之间的表现还可用于判断模型是否真正遵循视频规则。

## 6. 视频信息利用方式

在保持下游智能体和执行环境一致的条件下，比较不同的视频处理范式：

- **完整视频**：智能体直接观看原始教程视频；
- **无教程输入**：测量模型仅依赖先验知识时的能力；
- **文本描述**：将视频转换为 caption；
- **关键帧表示**：采用 TASKER 式方法提取与任务相关的参考帧；
- **技能表示**：采用 BrowserBC 式技能蒸馏，将示范信息转换为可复用的自然语言 skill；
- **知识注入**：采用 GUIDE 式方法，从视频中提取规划与界面定位知识并注入智能体；
- **轨迹表示**：采用 TongUI 式方法，将教程转换为结构化操作轨迹。

这些对照能够分析性能提升究竟来自原始视频理解，还是来自文本化、关键帧选择、技能抽象、知识提取或轨迹重建。[TASKER](https://vg-gui-tasker.github.io/)研究视频关键帧对 GUI 决策的作用；[BrowserBC](https://arxiv.org/abs/2606.32014)将交互示范蒸馏为可读取和复用的技能；[GUIDE](https://arxiv.org/abs/2603.26266)从教程视频提取规划与定位知识；[TongUI](https://ojs.aaai.org/index.php/AAAI/article/view/38229)将多模态网络教程转化为 GUI 操作轨迹。

## 7. 与 CL-Bench 的关系

[CL-Bench](https://arxiv.org/abs/2606.05661)通过在多个任务实例之间设置可学习的潜在结构，评测智能体能否从经验中持续学习，并将学习增益与模型原有能力区分开来。

VideoICL-Bench 延续这一核心评测思想，但将学习信号设为教程视频，并将最终输出设为真实环境中的在线操作。其关键评测对象不是智能体是否知道某个公开软件的常规用法，而是能否从单次视频示范中获得任务规则，并在新的交互实例中正确应用。

## 8. 预期贡献

VideoICL-Bench 将提供：

1. 一个连接视频理解、上下文学习与在线智能体执行的统一评测框架；
2. 一套由未见平台和反事实规则组成、能够隔离模型先验知识的受控数据集；
3. 一种通过规则 QA 与环境执行结果定位能力瓶颈的诊断机制；
4. 一组覆盖完整视频、文本、关键帧、技能、知识和轨迹表示的视频学习对照实验。

其最终目标是系统衡量智能体能否真正做到：**观看教程、理解规则、举一反三，并在真实数字环境中完成任务。**
