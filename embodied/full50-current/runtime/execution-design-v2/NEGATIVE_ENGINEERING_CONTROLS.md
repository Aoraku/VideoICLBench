# 原生工程负例策略

独立入口为 `execution_design_negative_expert.solve_execution_design_negative(author, control)`。
默认正例入口、模型提示词、局部示范和 QA 均不调用它。只能在独立工程验收世界使用；每个正/负控制使用独立 case identity 和原生轨迹，不在评测 episode 内换规则或重复启动。

所有操作沿用真实公开机器人平移、旋转、夹持动作。控制器只复制自己的私有计划，不改 scene spec、评分器基线、对象姿态、关节值或接触状态。返回值 `negative_condition_observed=null`，必须由采集器保存结束瞬间的原生证据，再由独立评分器核实。不得把函数返回、CPU 回归通过或分数下降单独认定为特定负例通过。

|控制|物理尝试|原生验收要求|
|---|---|---|
|wrong_members|E01/E09/E17/E39 用另一批次克隆件替代一个目标件；E20 优先替代一个待补充件；若如 seed4202/A 已无待补件，则保留全部初始件，完成正例局部步骤后在实测空位加入另一批次额外筹码。没有实测空位即失败|实测另一批次物体进入相关容器/层/托盘，或目标成员缺失；保留轨迹与接触|
|wrong_destination|完成前序流程后搬运到另一个可见收货区|实测载体位于错误站点，不能只有控制计划指向错误站点|
|wrong_rule|E01 换食品组合；E09 交换两组各一件；E17 一件放到另一层；E20 一格错一个数量；E39 交换受检顺序或旋转受检朝向|最终原生观测确实违反该任务实际启用的规则，其他故障不能代替规则反例|
|not_released|把载体移到正确站点后保持实测夹持，等待稳定采集，不调用释放|采集最终实际夹持/手指接触与 release 历史；必须在任何后续清理释放之前采集|

某策略缺少可抓取干扰件、无法保留初始件或缺少有效目标区域时抛 `UnsupportedNegativeControl`。运动不可达、丢失夹持或接触失败仍按实际异常保全，不能填造成功负例。所有五任务四类策略只是可执行控制计划；尚未完成原生矩阵验收，发布门禁继续关闭。
