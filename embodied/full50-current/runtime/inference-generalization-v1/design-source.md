# 具身 VideoICL：50题推理泛化设计

## 1. 范围与配置

本设计覆盖 E01–E50。每题真人 demo 与对应仿真 demo 的内容、A/B/C 对应关系均保持不变；仅定义推理阶段使用的物体、环境及任务提示。题号与[50题实录题单](TASKS.md)一致，视频对应关系见[150段视频索引](VIDEO_INDEX.md)。本文是任务配置规格，不代表全部推理仿真已实现。

| 推理组别 | 题数 | 物体 | 环境 | 测量内容 |
|---|---:|---|---|---|
| G0 · 基本复现 | 20 | 保留原物体，只允许轻微初态扰动 | 保留对应 demo 的仿真环境 | 同一关系与操作在相近初态下的执行能力 |
| G1 · 物体泛化 | 20 | 替换物体，保留规则依据的属性及所需操作条件 | 保留对应 demo 的仿真环境 | 将视频中的对应关系迁移到其他物体 |
| G2 · 物体与环境泛化 | 10 | 按 G1 原则替换物体 | **需要换环境：机械臂与桌面** | 在新物体、新环境下执行同一关系 |

合计 **50题、150个 A/B/C 推理配置**。每道题只属于一组，A/B/C 使用同一类替换资产和相同环境条件。A/B/C 是三个不同的示范关系：测试 A 使用 A demo，测试 B 使用 B demo，测试 C 使用 C demo，不把三条不同关系混成一条示范。不同初态种子属于重复测量，不增加题数。

这三组是**泛化范围**，不等同于 easy / medium / hard 的执行难度。任务分配首先看操作本身的负担：精细接触、薄片操作、滚动控制、倾倒和折叠等技能优先保留原物体与环境；颜色、形状、数量和空间关系等任务优先承担泛化。此判断依据操作机制，不能当作实测难度排名。

### 1.2 接触操作任务的范围

E42铲沿推球、E43导向滚球、E44纸板折叠、E45倾倒三球、E46铲面承托均属于G0。它们保留原对象、工具和环境，只允许不改变技能要求的轻微初态扰动。推球仍操作球，折叠仍操作原纸板，不通过更换材料、摩擦特性或机械臂叠加挑战。

## 2. 共同原则

1. **按技能负担选择迁移范围。**物体能替换不等于适合替换；操作本身已包含明显精细控制要求时，优先基本复现。G1允许同类别的新实例，不必强行跨类别；G2优先承载关系清晰、操作相对直接的任务。
2. **改变载体，保留关系。**颜色映射保留颜色，形状映射保留形状类别，尺寸关系保留大小排名，布局关系保留参照系。不能额外发明“汉堡对应苹果”之类视频中没有的类别映射。
3. **替换不改变核心动作。**套柱对象仍有通孔，套叠对象仍能套入，夹取对象仍适合夹持；推动、承托、倾倒、滚动与拧动不能互相替代。G1/G2可以保留原工具，只替换被操作对象。
4. **初态变化适度。**允许小幅平移、轻微打散，不靠极端遮挡、巨大尺寸变化或新增障碍制造泛化。关系依赖的标签、车头、前后与左右参照必须可见或在提示中明确。
5. **提示点明学习哪种关系，不给出关系的答案。**例如“按视频展示的颜色与图形对应关系”，不写“红色放圆形”。下表的 demo A/B/C 和验收边界供设计与评审人员使用，不能整表作为 agent prompt。
6. **不从固定示范强推无依据的泛化。**E26 保留数字9和1；品牌选择保留品牌；不要求模型自行猜测新增类别、颜色或运算。新物体的相关属性应能直接观察，无须额外查表。
7. **不改变示范覆盖范围。**目标集合、数量、顺序及工具使用要求按对应 demo 保留；只在原任务需要时判过程，不给普通选放题额外加顺序要求。
8. **G2只指定换环境。**机械臂和桌面的具体设计由实施方决定。更换后仍须保证可达、可抓、可见及方向参照一致；不能因为更换机械臂而取消原操作需要的辅助接触能力。

颜色替换示例：如果 demo 使用红、绿、黄，可以用红苹果、绿梨、黄色水果；本题集中多题实际使用**红、绿、蓝**，因此采用红苹果、绿梨、蓝色收纳罐，不能擅自用黄色水果替代蓝色。跨类别本身即可构成物体泛化，不要求三个物体必须都是水果。

## 3. 逐题配置

表中“推理提示”可直接作为相应任务的 inference prompt，A/B/C 共用提示文本，由各自 demo 决定答案。“验收边界”是资产和评测要求，不是额外给 agent 的分步操作说明。所有任务均应基于真实接触、支撑、容纳或事件状态验收，不能仅因触发界面按钮就判成功。

### 3.2 G1 · 物体泛化（20题）

本节只换物体，环境保持与对应仿真 demo 一致。食品、蜡烛等可使用刚体道具模型，不引入食用、点火、破碎或软体模拟要求。

## 4. 判分与实施要求

### 4.1 关系与执行分开记录

每次测试至少记录完整任务是否成功，并尽可能记录对象级或事件级结果。分项分数只解释错误位置，不取代完整成功率。

| 任务特征 | 主要检查 | 分项记录示例 |
|---|---|---|
| 颜色、形状、身份映射 | 每个对象到正确目标；不处理的对象保持 | E04：3件分别是否放对；E09：组成员匹配，忽略无标签分区的排列 |
| 层序、布局、朝向 | 相对本轮初态或静态参照的关系，以及真实支撑 | E14：4层次序；E15：位置和朝向分别记录 |
| 选取与数量 | 目标集合、总数、未选对象约束 | E20：3区分别是否补到目标总数；E36：盒内总数与是否误动 |
| 时间顺序 | 真实接触或首次入目标事件的有序序列 | E21/E24：入盘、入盒顺序；E29：敲击序列含端点重复 |
| 工具操作 | 对象结果正确，同时确实使用相应工具完成关键运输或作用 | E37：螺丝刀驱动松脱；E42：铲沿推动；E50：夹口承载运输 |
| 轨迹与状态 | 穿越、关合、正反面等任务特有条件 | E43：经过区域；E18：交付后关回抽屉；E31：盘面朝向 |

几何容差应随物体尺寸、目标区域和物理稳定性合理设定，不能照搬原物体的绝对坐标阈值。容差用于容纳执行误差，不得把错误目标、错误朝向或错误顺序也判成功。规格中有“左起”“从顶端”等身份定义时，必须保存初态身份，不随抓取次序重新编号。

### 4.2 资产可用性检查

- 每题 A/B/C 的目标状态都可通过真实操作达成，不能只验证其中一个版本；尤其检查 E02/E35 稳定叠放、E38孔柱间隙、E44折后定形、E48卡座容量、E50夹口尺寸。
- 替换资产保留清楚的相关属性：颜色不混淆，尺寸无并列，朝向有明确端点；E09/E17保留完整交叉属性，避免颜色与形状共变。
- 初态不直接满足目标；需要区分的变换不能因为对称布局而得到同一结果，例如 E11 的布局与 E15 的朝向。
- 目标语义与任务状态以同一来源提供给渲染、控制和评测；可见属性与评测中的对应关系必须一致，不能用冲突的内部标签决定答案。
- 同题 A/B/C 尽量使用配对初态，防止颜色顺序被固定摆位泄露。每次评测只提供该版本 demo，不展示规则表或验收答案。

### 4.3 结果解释

G0、G1、G2分别报告成功率和分项结果。由于三个组使用不同题目，组间成功率差异同时包含任务本身的差异，不能直接解释成纯粹的物体或环境泛化损失。若需量化损失，可为G1/G2额外运行同题同版本的原物体、原环境对照；对照复用既有题号和 demo，不计入50道主题。
